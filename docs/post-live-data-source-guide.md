# 关播页展示数据与来源说明

本文档汇总 LIVE Studio Genie 当前关播页展示的全部信息，并区分真实浏览器采样、真实会话状态、Mock 数据、派生指标和 AI 生成内容。

## 1. 数据类型说明

| 类型 | 含义 |
| --- | --- |
| 真实监控 | 直播期间通过浏览器摄像头、Web Audio 或 MediaPipe 持续采集的数据 |
| 真实会话状态 | 用户在本次页面会话中的选择、操作和实际直播计时 |
| Mock 数据 | 由前端配置和 `AudienceEventAdapter` 生成的演示数据 |
| 派生数据 | 根据真实数据、Mock 数据或两者混合计算出的结果 |
| AI 生成 | 将本场报告提交给 Genie 后生成的总结与建议 |

当前项目尚未连接 TikTok 直播间服务端，因此观众、进房、评论、粉丝和礼物等经营数据均不是线上真实数据。

## 2. 页面顶部信息

| 展示内容 | 来源 | 类型 |
| --- | --- | --- |
| 直播主题 | 主播播前选择或填写的主题 | 真实会话状态 |
| 直播类型 | 聊天陪伴、音乐现场、游戏直播等播前选择 | 真实会话状态 |
| 演示策略 | 正常、画面偏暗、声音偏小、互动转冷、网络卡顿或 PK 冲刺 | 真实会话状态 |
| 本场时长 | 从点击 `GO LIVE` 到确认结束直播的页面运行时间 | 真实会话状态 |

## 3. 观众经营数据

### 3.1 页面展示项

| 指标 | 当前生成方式 | 类型 |
| --- | --- | --- |
| 总观看 | 当前 Mock 在线人数加上“每分钟进房人数 × 直播分钟数” | Mock 派生 |
| 峰值在线 | 使用关播时的 Mock 在线人数，不是历史峰值扫描结果 | Mock |
| 新增粉丝 | Mock 进房人数乘以直播分钟数，再按 `22%` 转化率估算 | Mock 派生 |
| 评论数 | Mock 每分钟评论数乘以直播分钟数，且不少于当前评论窗口数量 | Mock 派生 |
| 礼物数 | 当前 Audience Snapshot 中两条 Mock 礼物记录的数量之和 | Mock |
| 新观众留存 | 当前演示策略配置的留存率 | Mock |

为保证短时间比赛演示也能看到完整数据，总观看、评论和新增粉丝计算时会按至少一分钟处理。

### 3.2 当前未展示字段

`PostLiveReport` 内部还会计算：

```text
钻石数 = 礼物数 × 12
```

该字段目前会保留在报告对象中，但没有显示在关播页指标卡中。

## 4. 整场真实监控

直播开始时会创建新的会话聚合器，并记录开播后产生的有效样本。聚合器根据每项指标的 `updatedAt` 去重，避免其他状态更新造成重复统计。

只记录满足以下条件的数据：

- 指标状态为 `ready`。
- `updatedAt` 晚于该指标上一条已记录样本。
- 样本产生于本次点击 `GO LIVE` 之后。

### 4.1 画面亮度

数据来源：摄像头中心区域 Canvas 采样，默认每 `900ms` 更新一次。

关播页展示：

- 整场平均亮度，例如 `62 / 100`。
- 整场平均评分。
- 整场最低评分。
- 异常样本占比。
- 有效样本数。

### 4.2 麦克风电平

数据来源：Web Audio 对麦克风音频执行 RMS 与 dB 分析，默认每 `250ms` 更新一次。

关播页展示：

- 整场平均麦克风电平，例如 `-24 dB`。
- 整场平均评分。
- 整场最低评分。
- 异常样本占比。
- 有效样本数。

### 4.3 人脸画面占比

数据来源：MediaPipe Face Landmarker 计算人脸关键点、画面占比和构图位置。

关播页展示：

- 整场平均人脸画面占比，例如 `31%`。
- 整场平均评分。
- 整场最低评分。
- 异常样本占比。
- 有效样本数。

### 4.4 异常判定

聚合器沿用实时监控指标的 `tone`：

- `good`：正常样本。
- `warn` 或 `bad`：异常样本。

计算方式：

```text
异常占比 = 异常样本数 ÷ 有效样本数 × 100%
```

如果没有摄像头、麦克风权限，或者直播期间没有产生有效数据，对应指标显示“暂无有效样本”，不会生成伪造值。

## 5. Genie 使用情况

| 展示内容 | 来源 | 类型 |
| --- | --- | --- |
| 已采纳建议数 | 实时监控建议中已经应用且可操作组件已经移除的建议数量 | 真实会话状态 |

当前统计的是实时建议队列中的采纳记录，不包含普通 Genie 对话生成组件的历史累计。

## 6. 直播表现指数

直播表现指数属于真实监控和 Mock 经营数据共同参与的派生分数。

当前计算因素：

- Mock 新观众留存。
- 有效真实监控指标的平均评分。
- 实际采纳 Genie 建议数量。
- 没有真实设备样本时，监控部分使用默认分 `70`。
- 最终结果限制在 `60` 至 `96` 分。

因此该指数用于 Demo 内部对比，不是 TikTok 官方直播评分。

## 7. 下一场经营建议

### 7.1 策略建议

根据本场选择的演示策略生成，例如：

- 画面偏暗：保存本场补光参数为播前预设。
- 声音偏小：复用调整后的人声与 BGM 增益组合。
- 互动转冷：提前发布点歌投票。
- 网络卡顿：准备低负载画面配置。
- PK 冲刺：强化阶段目标和剩余差值。

类型：规则生成，输入为真实策略选择。

### 7.2 观众承接建议

根据 Mock 新观众留存是否达到 `45%` 生成。

类型：Mock 数据驱动。

### 7.3 真实监控建议

聚合器会从亮度、麦克风和人像构图中选择：

1. 异常占比最高的指标。
2. 异常占比相同时，选择平均评分最低的指标。

然后生成对应的设备或画面优化建议。没有有效监控样本时不会生成此类建议。

类型：真实监控数据驱动。

### 7.4 Genie 协作建议

根据本场是否实际采纳过实时建议，决定下一场应复用已验证配置，还是加强播前 AI 检查。

类型：真实会话状态驱动。

“预计评论率 +12%”“预计留存 +6%”等影响标签属于固定 Demo 文案，不是预测模型计算结果。

## 8. AI 深度复盘

进入关播页后，系统会自动向 Genie 提交以下上下文：

- 直播主题、直播类型和演示策略。
- 真实直播时长。
- Mock 总观看、峰值在线、新增粉丝、评论、礼物和留存。
- 真实亮度、麦克风和人像构图聚合摘要。
- 实际采纳 Genie 建议数量。

每项真实监控摘要包含：

```text
平均业务值
平均评分
最低评分
异常占比
有效样本数
```

AI 请求本身是真实调用，但其结论使用的是“真实监控 + 真实会话状态 + Mock 经营数据”的混合输入。Prompt 会明确要求模型不得虚构未提供的平台数据。

如果 AI 接口不可用，页面保留本地规则生成的兜底总结，不影响数据复盘展示。

## 9. 开放式追问

主播可以在关播页输入：

- 对本场直播的主观感受。
- 希望下一场优化的方向。
- 开场、互动、画面、声音或设备问题。
- 希望复用的本场设置。

系统会把问题和完整的 `PostLiveReport` 一起提交给 Genie。快捷问题是本地预设文案，回答来自真实模型请求。
