# LIVE Studio Genie 功能实现状态与操作指南

本文档基于当前 `main` 分支实现整理，用于比赛演示、功能验收和后续开发交接。

## 1. 状态说明

- **已实现（真实能力）**：接入浏览器、MediaPipe 或 Web Audio 的真实运行能力。
- **已实现（Demo/Mock）**：交互链路完整，但业务数据由本地模拟器生成。
- **部分实现**：已有可演示的相近能力，但尚未覆盖完整需求。
- **未实现**：当前界面和数据层均没有对应能力。

## 2. 通用能力实现总览

按 Demo 演示口径统计：**13 项已实现、0 项部分实现、1 项未实现**。

| 分类 | 能力 | 状态 | 当前实现 |
| --- | --- | --- | --- |

## 3. 数据真实性边界

### 3.1 真实数据

- 摄像头画面与摄像头亮度。
- 麦克风音频、电平、静音和增益。
- 人脸关键点、人像占比和构图状态。
- 屏幕、窗口或标签页投放。
- 本地美颜、美妆、虚拟背景和人脸道具。
- 配置 API Key 后的 Genie 模型请求。

### 3.2 模拟数据

- 在线观众数、近一分钟进房人数和评论密度。
- 实时评论、礼物动态和评论关键词洞察。
- PK 对手、比分和倒计时。
- LIVE Goal 的自动增长与“模拟礼物 +250”。
- 投票由当前浏览器点击模拟，不连接真实直播间评论。

### 3.3 当前缺口

- 真实直播间 IM、进房、礼物和观众画像数据源。
- 观众性别、年龄分布。
- 真实评论驱动的心愿自动聚类、排序与服务端同步。
- 真实推流、真实连麦 PK 和服务端直播状态同步。

## 4. 启动与权限

### 4.1 启动项目

环境要求：

- Node.js 20+
- npm 10+
- 最新版 Chrome 或 Edge

在项目根目录执行：

```bash
npm install
npm run dev
```

打开终端显示的地址，默认是：

```text
http://localhost:5173
```

### 4.2 浏览器权限

首次进入工作台后允许：

- 摄像头权限：用于真实预览、亮度、人像占比、美颜、美妆和道具。
- 麦克风权限：用于声音电平、静音和增益调节。
- 屏幕共享权限：点击“游戏投屏”后，由浏览器弹窗选择目标窗口。

拒绝权限不会阻断页面，其对应指标会显示未连接、设备不可用或演示画面。

## 5. 推荐完整体验路径

### 5.1 首页与工作台生成

1. 打开首页。
2. 点击“聊天陪伴”“音乐现场”“游戏直播”或“其他”，可直接进入统一直播工作台。
3. 也可以在“本场主题”中输入直播主题，通过 Enter 或“召唤精灵”进入工作台。
4. 熟悉流程时可点击“我很熟，直接进入专业模式”。

### 5.2 完成播前准备

播前和直播中使用相同的三列控制台结构，不再切换到独立设置页面：

- 左侧显示摄像头、麦克风和网络预览状态；Gift、Comment 区域保持空白，也不加载观众数或进房数据。
- 中间显示真实摄像头或演示画面，下方显示直播准备度和 `GO LIVE` 按钮。
- 右侧依次提供画布布局、画面与音频、直播信息与内容、互动预热四项准备任务。

推荐操作：

1. 在“单人竖屏”和“秀场舞台”之间选择布局并确认。
2. 检查补光、对比度、麦克风和设备状态。
3. 完善直播预告、主播介绍、主题说明、封面和首 3 分钟脚本。
4. 配置互动预热文案和开场投票。
5. 点击中间列下方的 `GO LIVE`，在当前页面原位切换到直播中。

点击 `GO LIVE` 后，准备度模块自动隐藏，礼物、评论、在线观众、进房指标、实时建议及对应组件开始加载。

### 5.3 选择典型场景

典型场景仅在直播中启用。播前保持原有准备流程、画面参数和空数据状态；点击 `GO LIVE` 后，再点击左上角 TikTok 图标打开典型场景菜单：

- **正常场景**：保留自然评论、送礼和进房数据，并根据实时信号动态生成建议。
- **画面转暗**：面部曝光低于 `35/100` 时优先召回亮度调节。
- **声音偏小**：人声清晰度低于 `28/100` 时优先召回麦克风。
- **评论区转冷**：评论低于 `16/min` 时生成可选择、编辑并直接采用的口播建议。
- **评论区活跃**：评论高于 `75/min` 时召回观众心愿，承接当前互动热度。

进入直播时默认使用正常场景；手动选择四个演示场景之一后立即切换对应模拟数据，也可随时切回正常场景。返回直播前设置时会恢复开播前保存的画面与音频参数。

典型场景启用后，右侧建议和组件严格使用上述映射，不会混入其他监控指标或评论分析产生的组件。

接纳与当前策略匹配的 AI 建议后，评论会展示 `10` 秒针对调整结果的认可反馈，随后恢复正常评论。详细状态流和各策略映射见 [评论区演示策略说明](./audience-comment-strategy.md)。

## 6. 直播控制台操作

### 6.1 监控指标

进入直播状态后，左侧每 `10` 秒刷新表现最好的两个指标和下降最明显的两个指标。评论列表会铺满输入框上方的全部剩余空间，最新消息自动跟随到底部；用户向上查看历史时不会被强制拉回。

正常场景的模拟评论会按声音、画面、卡顿、内容点播、礼物互动和正向反馈分阶段轮换。每个问题主题会形成短时聚类，驱动右侧依次生成音频调节、画面调节、流畅度优化、互动投票或 LIVE Goal 等不同建议组件。

正常场景下，右侧每 `5` 秒在后台比较一次监控指标、最新评论和画面状态，并使用基于计划起点校准的定时器避免累计漂移。后台分析不会直接改写右栏；仅在主播提交 Prompt 后，分析结果才会随模型回复更新到对话中。典型问题场景继续使用各自的严格组件白名单。

发送 Prompt 后，整个右栏进入聊天模式。召回组件作为 Genie 消息直接显示在对话中，不再保留独立组件区。输入文字本身不会改变右栏内容；多轮消息和已召回组件会持续保留，并通过浏览器本地存储在刷新后恢复。对话顶部的删除图标可在二次确认后清空全部消息与召回记录。模型协议、变量名和内部参数会在回复展示前过滤。该对话流程在直播前和直播中共用。文字源、目标源、LIVE goal、观众心愿和投票发布到中间预览区后支持点击选中、拖拽移动、删除；选中时右栏自动展示对应详情和配置。

### 6.2 摄像头与麦克风

- 点击“开启摄像头”重新请求设备权限。
- 摄像头连接后，按钮显示“摄像头已连接”。
- 点击“麦克风”可静音，再次点击恢复。
- 左侧切换到“排障”可查看实时 dB。

### 6.3 BGM

1. 点击“播放 BGM”启动本地生成的环境和弦。
2. 切换到“排障”场景。
3. 在右侧调整“麦克风”和“BGM”滑杆。
4. 先点击“预览调整”，确认后点击“确认音频调整”。
5. 已应用后可点击“撤回最近一次调整”。

### 6.4 游戏投屏与画中画

1. 点击“游戏投屏”。
2. 在浏览器弹窗中选择屏幕、游戏窗口或标签页。
3. 应用会自动切换到“Studio 视图”，摄像头显示为画中画。
4. 点击“编辑布局”后拖动画中画，拖动边缘调整尺寸。
5. 点击“锁定布局”结束编辑。
6. 编辑状态下点击“重置布局”恢复默认位置和尺寸。
7. 点击“停止投屏”，或使用浏览器共享栏停止共享。

浏览器不保证所有独占全屏游戏都能被捕获，比赛演示建议共享普通窗口或浏览器标签页。

### 6.5 画面亮度与对比度

1. 左侧选择“画质”。
2. 右侧调整“补光”“对比度”“暖色”滑杆。
3. 点击“预览调整”查看临时效果。
4. 点击“应用柔光方案”保存参数。
5. 点击“撤回最近一次调整”恢复上一次正式参数。

预览参数不会直接覆盖已提交配置；切换场景时会清理未应用的预览。

### 6.6 美化工具

点击底部“美化工具”，右侧提供五个 Tab：

- **整套**：清透日常、甜美直播、舞台高光、未来科技，并显示全部微调项。
- **美颜**：原生、自然、柔焦、亮颜。
- **美妆**：无妆、裸妆、甜美、舞台、冷感。
- **道具**：仅保留星光、眼镜和爱心三个图标入口。
- **背景**：使用滑杆控制虚化程度，四个虚拟背景使用图标入口。

美颜滑杆：

- 柔肤、提亮、暖肤、对比度、饱和度。
- 美白、红润、清晰。

美妆滑杆：

- 口红、腮红、眼影，可同时调整颜色和强度。
- 眼线、高光。

操作顺序：

1. 选择整套预设，或分别选择美颜、美妆、道具和背景。
2. 调整滑杆时进入预览状态。
3. 点击“应用美化方案”提交当前效果。
4. 点击“撤回最近一次调整”恢复上一次效果。

摄像头原始画面不会上传给模型。MediaPipe 推理和 Canvas 合成都在浏览器本地执行。

### 6.7 互动投票

方式一：

1. 点击底部“互动组件”显示投票预览。
2. 右侧点击“发布互动挂件”。
3. 在画面中的选项按钮上模拟投票并查看百分比。
4. 投票会在设定时间结束后自动收起。
5. 再次点击底部按钮可手动隐藏组件。

方式二：

1. 左侧选择“互动”。
2. 使用右侧 Genie 推荐的点歌投票。
3. 按“预览调整”与“发布互动挂件”完成上屏。

当前投票点击发生在主播端 Demo，不读取真实评论数字。

画面中的观众投票、LIVE goal 和观众心愿均可直接点击；点击后右侧会切换到对应组件的详细设置面板，使用“返回实时建议”退出配置。

### 6.8 PK 与 LIVE Goal

1. 点击底部“发起 PK”，画面切换为双人模拟 PK。
2. 右侧显示“本轮冲刺目标”。
3. 点击“预览调整”查看目标挂件。
4. 点击“发起冲刺目标”正式上屏。
5. 目标每 3 秒自动增加 120 分。
6. 点击画面中的“模拟礼物 +250”加速进度。
7. 达标后显示“目标达成”。
8. 点击“结束 PK”返回普通直播画面。

PK 对手、比分和目标增长均为前端模拟，不会创建真实连麦。

### 6.9 结束直播与播后监控复盘

1. 直播中点击顶部“结束直播”，在确认弹窗中检查时长、当前观看和已采纳建议数。
2. 点击“结束并生成复盘”后，应用停止摄像头、麦克风处理、投屏和 BGM。
3. 播后页的观众、评论、礼物、涨粉和留存仍为 Demo 数据。
4. “整场真实监控”来自本场直播期间的浏览器采样，包含：
   - 画面亮度平均值、平均/最低评分、异常占比和有效样本数。
   - 麦克风平均 dB、平均/最低评分、异常占比和有效样本数。
   - 人脸平均画面占比、平均/最低评分、异常占比和有效样本数。
5. 聚合器按指标 `updatedAt` 去重，只记录直播开始后的 `ready` 样本；无设备权限时显示“暂无有效样本”。
6. Genie 自动复盘和后续追问都会携带整场真实监控摘要与观众 Demo 数据，并明确禁止虚构未提供的平台数据。

## 7. Genie AI 操作

### 7.1 配置

在项目根目录创建 `.env`：

```env
GENIE_MODEL_AK=你的模型访问密钥
GENIE_MODEL_BASE_URL=https://aidp-i18ntt-sg.tiktok-row.net
```

修改环境变量后需要重启开发服务器。

### 7.2 使用方式

在右下角输入问题并按 Enter，或点击发送按钮。示例：

```text
画面亮度加 10，对比度加 5，暖色加 3
麦克风提高 6 dB，BGM 降低 4 dB
创建一个“下一首唱什么”的投票
发起一个 10000 分的 LIVE Goal
根据当前亮度给我一套自然美颜
柔肤 20，美白 15，口红 30，戴黑色墨镜
```

输入 Prompt 后，整个右侧栏会切换为 Genie 聊天界面。输入期间不提前召回组件；发送后才会把 Prompt、当前直播画面帧和实时指标交给模型分析，再展示用户消息、模型回复及对应的可操作组件。点击“返回当前工作台”可恢复原有播前任务或直播监控视图。

正常场景每 `5` 秒在后台检查一次画面、监控和评论差量。高优先级单条反馈可立即进入候选，同类普通反馈累计两条后触发；同类建议使用冷却窗口避免重复请求。后台结果作为下一次 Prompt 的上下文，不会自行改变右栏内容；模型不可用时会保留本地规则分析作为提交后的降级参考。

模型可生成以下可信组件：

- 画面调节
- 音频调节
- 相机美化
- 观众投票
- LIVE Goal

生成组件后仍需经过“预览 -> 应用”流程。所有 Widget 都经过 Zod Schema 和白名单注册表校验，未知组件、任意 HTML 和任意 JSX 不会被渲染。

请求期间可取消。模型请求通过 Vite 服务端代理读取 `.env` 中的 `GENIE_MODEL_AK`，密钥不会进入浏览器代码；超时或失败时，Genie 会使用本地意图识别生成可执行回复和对应组件。

## 8. 非通用能力

### 8.1 Onboarding

- 按直播类型生成工作台。
- 支持自定义主题。
- 支持直接进入专业模式。

### 8.2 播前任务

- 画布布局确认。
- 画风检测建议。
- 标题和开场脚本预览。
- 互动开场配置。
- 准备度进度和 GO LIVE 流程。

### 8.3 移动端与 Studio 预览

- “移动端预览”用于观察竖屏观众侧效果。
- “Studio 视图”显示画布辅助线，并用于投屏和画中画编辑。

### 8.4 模拟 PK

- 双人画面、比分、倒计时和目标挂件。
- 用于展示直播流程，不包含真实连麦、推流或服务端结算。

### 8.5 动态评论与礼物

- 评论、礼物、观众数和进房数据按固定节奏变化。
- 不同演示场景使用不同评论语料。
- 评论关键词结果可驱动排障建议。

### 8.6 安全预览与撤回

- 画面、音频、美化、投票和 LIVE Goal 均支持预览。
- 应用后保留上一次正式状态，可执行一次撤回。
- 切换场景时清理未提交预览，避免临时参数污染正式状态。

## 9. 比赛演示建议顺序
